# 项目总结：数据组职责

这个项目的核心目标是为《Overcooked》（胡闹厨房）游戏开发一个“玩家意图置信度驱动的支持型 AI”。不同于传统只追求高分的 AI，这个 AI 旨在理解人类玩家的意图（比如玩家想干什么），从而决定何时协助玩家、何时让渡主导权，提供更好的合作体验。

作为“数据组（Data Team）”，你的核心职责是：**构建任务级玩家意图数据集**（交接给 Agent 组训练模型使用）。

你需要完成的具体工作总结如下：

## 1. 定义与提取标签（Labeling）
* 将玩家杂乱的历史动作轨迹（移动、转向等）转化为 **5种明确的中期子任务意图**（拿食材、放进锅、拿盘子、装盘、上菜）和 **1种未承诺状态**（`no_commitment`）。
* **重要区别**：`no_commitment` 是一种可以学习的行为语义（表示目前没有足够证据表明玩家已承诺某一任务，不允许触发 Assist）；而 `unknown/invalid` 表示数据缺失、冲突或无法可靠监督的无效数据，**绝不参与这六类分类训练**。
* **统一语义**：模型预测的是任务倾向，不是单步行为。控制器不能再对六类概率直接取最大值后决定介入强度。

## 2. 构造特征与防止数据穿越（Feature Engineering）
* 基于历史窗口 W 提取观测特征（位置、动作、环境布局等）。
* **极其严格地防止未来数据泄漏**：未来的成功事件只能用于打标签，绝不允许出现在模型的特征输入（Input）中。

## 3. 科学的数据集切分（Data Splitting）
* 必须按整局游戏（episode）、玩家策略或随机种子来切分训练集/验证集/测试集。严禁将同一局游戏的不同时间窗口随机分到不同集合中（防止数据泄漏）。

## 4. 产出与验收标准（Deliverables）
* 先用小批量数据做测试（smoke test），跑通全链路后再生成全量数据（formal）。
* 产出规范的交接包文件（如 `cole_task_intent_v0.2`），包括标签定义文件（`label_definitions.md`）、意图边界核对日志（`no_commitment_audit.jsonl`）、证明没有发生数据泄漏的质量报告（`quality_report.json`，需包含输入白名单）以及能被 Agent 组直接读取的 `sequence_dataset.py` 等脚本。
