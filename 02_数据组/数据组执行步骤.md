# 数据组接收环境组文件后的具体执行步骤

在接收到环境组的交接包（`platform_data_handoff_v2`）后，数据组的核心任务是将其转化为可信的任务级玩家意图数据集，并交接给 Agent 组。具体执行步骤如下：

## 1. 建立独立环境与最小测试
- **环境搭建**：创建并激活本组的独立运行环境（推荐 `cole-data` Python 3.10），并在 `setup_log.md` 记录环境依赖。
- **只读挂载**：将环境组的交接包复制到只读输入目录，记录版本和来源，严禁直接改写。
- **最小测试**：运行环境组的 `validate_raw_trajectory.py` 和 `replay_episode.py` 验证交接轨迹，确保全链路畅通后再进入开发。

## 2. 阶段 D1：冻结标签定义与提取
- **语义转换**：将玩家的杂乱动作轨迹转化为 5 种明确的中期子任务意图（拿食材、放进锅、拿盘子、装盘、上菜）和 1 种未承诺状态（`no_commitment`）。强调：模型预测的是**任务倾向**，不是单步动作。
- **无效数据隔离**：严格区分 `no_commitment`（可学习的语义，但不能触发 Assist）与 `unknown/invalid`（数据损坏或冲突）。将后者标记为 `unknown/invalid`，设置分类掩码（`classification_mask=false`）以确保其绝对不参与这六类的模型训练。
- **人工核对**：抽查各任务类的正负例，重点审核 `no_commitment` 与短暂走位、改向、被堵路等情况的边界，记录在 `label_definitions.md` 和核对日志中。

## 3. 阶段 D2：构造监督窗口与防止数据穿越（特征工程）
- **特征提取**：仅允许基于历史窗口（如历史位置、动作、布局等）提取观测特征。
- **严防数据泄露**：未来的成功事件或状态只能作为监督信号（用于打标签），**绝不允许**出现在模型的特征输入（Input）中。

## 4. 阶段 D3：科学的数据集切分与质量控制
- **数据切分**：严格按整局游戏（episode）、玩家策略或随机种子来切分训练集/验证集/测试集。严禁将重叠的时间窗口随机分入不同集合，以防数据泄露。
- **灰度发布机制**：先生成小批量数据（smoke 测试版，每类约 200 条）跑通全链路，通过验证后再生成全量数据（formal 正式版）。
- **质量报告**：产出 `quality_report.json`，必须审计并报告六类标签分布、`unknown` 比例、数据泄露检查、NaN/Inf 异常、输入白名单以及人工抽查结果。

## 5. 阶段 D4：冻结训练接口与正式交接
- **定义接口**：输出格式化的训练数据规范（如 `features`, `history_mask`, `intent_target` 等）。
- **交付验收**：生成最终交接包（`cole_task_intent_v0.2`），其中包含拆分好的数据集文件、标签定义文档、质量检查报告，以及能被 Agent 组直接调用的 `sequence_dataset.py` 脚本，交付并进行现场验收。
